# 检查器：CLI、能力与边界

本文是 `scripts/ste-lint.mjs` 的接口与机械检查能力说明。英文改写规则以 [SKILL.md](../SKILL.md) 为准，中文改写规则以[中文简明技术写作规范](chinese-writing-rules.md)为准。检查器仅依赖 Node.js 22 或更高版本的内置模块，不需要 npm 依赖，不调用模型、外部词典或 NLP 服务。

## 输入与 CLI

检查文件，也可以不传文件名而从标准输入读取：

```bash
node scripts/ste-lint.mjs --text-type instruction instructions.md
node scripts/ste-lint.mjs --text-type description description.md
node scripts/ste-lint.mjs --language zh --text-type instruction zh-instructions.md
node scripts/ste-lint.mjs --language zh --list-rules
printf '%s\n' 'The job may have failed.' | node scripts/ste-lint.mjs --json
node scripts/ste-lint.mjs --baseline 5 legacy.md
node scripts/ste-lint.mjs --disable passive-voice,present-perfect text.md
node scripts/ste-lint.mjs --list-rules
node scripts/ste-lint.mjs --list-rules --json
node scripts/ste-lint.mjs --selftest
```

| 参数 | 含义 |
|---|---|
| `FILE [FILE ...]` | 以 UTF-8 读取一个或多个文件；省略时读取标准输入。 |
| `--text-type instruction` | 所有输入按指令检查，单句上限为 20 词。 |
| `--text-type description` | 所有输入按说明检查，单句上限为 25 词；这是默认值。 |
| `--language en` | 使用英文规则与词数上限；这是默认值。 |
| `--language zh` | 使用中文规则与字数上限（指令 20 字、说明 30 字）。 |
| `--json` | 输出结构化结果。检查报告包含 `schema_version`（整数 `1`）、`language`、`text_type`、`max_words`、`violations`、`count`、`hard_count`、`baseline`、`words` 和 `per_100_words`。 |
| `--baseline N` | 允许硬性问题总数不超过非负整数 `N`；默认 `0`。 |
| `--disable rule1,rule2` | 按规则 ID 禁用检查。规则 ID 以 `--list-rules` 为准；未知 ID 或空项会报参数错误。 |
| `--list-rules` | 显示规则 ID、等级及能力说明，可与 `--json` 配合。 |
| `--selftest` | 使用 `node:test` 运行 `tests/test_ste_lint.mjs`，只覆盖 Node 检查器回归。 |

文本类型由调用方选择，检查器不会自动识别指令或推断 Strict 模式。混合文档应拆成不同输入并分别设置类型。语言同样由调用方用 `--language` 选择，不自动识别；`en` 使用英文规则与词数上限，`zh` 使用中文规则与字数上限。

`--selftest` 必须单独使用；`--list-rules` 仅可与 `--json` 和 `--language` 组合。两种操作互斥，都不能携带文件、`--baseline`、`--disable` 或 `--text-type`；即使显式传入默认值也会报错。无效组合返回 `2`，不会忽略选项后继续运行。普通文本检查可以组合这些检查参数。

正常检查时，硬性问题总数超过基准返回退出码 `1`，否则返回 `0`。advisory 不增加硬性问题数。参数或输入错误返回退出码 `2`，并提供错误说明。

## 规则等级

运行时的规则 ID、等级、类型和限制以 `--list-rules` 返回的统一元数据为准。下表解释当前规则的能力，不作为另一份规则配置维护。

每条规则同时登记元数据和可调用的执行器，`lint()` 统一执行目录中的检查器。登记时拒绝缺失执行器和重复 ID，新增规则不能只出现在帮助中而不参与检查。

“硬性”指确定出现受支持的形式，不代表判断出语义错误或官方 STE 不合规。结构化结果保留等级名称 `advisory-free`（硬性）和 `advisory`（建议）；规则类型为 `deterministic` 或 `heuristic`。`--list-rules --json` 输出 `schema_version` 和 `rules`，每条规则含 `id`、`level`、`type`、`description`、`limitations`。

| 规则 ID | 等级 | 检查内容与限制 |
|---|---|---|
| `semicolon` | 硬性 | 正文分号；代码区域不参与检查。 |
| `long-sentence` | 硬性 | 正文句子超过选定文本类型的词数上限；句子切分是启发式处理。 |
| `dangling-conjunction` | 硬性 | 受支持列表项末尾的英文 `and` 或 `or`；不判断完整句法。 |
| `phrasal-verb` | advisory | 内置的有限短语动词模式，不涵盖所有英语短语动词。 |
| `nominalization` | advisory | 内置动作名词化模式，不进行完整词性或语义分析。 |
| `marketing-adjective` | advisory | 提示部分质量主张；不能证明没有依据，也不能要求删掉原文程度或虚构数据。 |
| `passive-voice` | advisory | 正则识别可能的被动语态；不猜测 actor，也可能匹配形容词。 |
| `present-perfect` | advisory | 正则识别部分复合时态；保护部分情态完成式，如 `may have failed`，保留原有否定和副词范围，不截断合法长前缀；不是完整语法分析。 |
| `synonym-rotation` | advisory | 文件内出现词表中的多个近义词时提示；不能确认它们描述同一概念、对象或动作。 |

`--language zh` 启用下列中文规则。中文规范、计数口径和完整规则见[中文简明技术写作规范](chinese-writing-rules.md)。

| 规则 ID | 等级 | 检查内容与限制 |
|---|---|---|
| `zh-semicolon` | 硬性 | 正文含全角 `；` 或半角 `;`；代码区域不参与检查。 |
| `zh-long-sentence` | 硬性 | 句子字数超过中文上限；按汉字与西文词计数，按 `。！？` 分句，不实现完整中文语法分析。 |
| `zh-dangling-conjunction` | advisory | 启发式提示受支持列表项末尾的连接词（和、或、以及、并且、或者、同时）；后缀匹配无法确定中文词边界，会误报「总和」「饱和」等词，不影响退出码。 |
| `zh-list-required` | advisory | 一段中出现三个或更多要求强度词（必须、应当、可以、不得等）时提示改为列表；不判断要求是否真的对应不同操作。 |
| `zh-paragraph-topic` | advisory | 段落句子数超过 6 句目标时提示分段或合并；按 `。！？` 计数，不判断主题是否真的不同。 |
| `zh-multi-action` | advisory | 句内出现并列连接词时提示可能包含多个动作；不判断分句是否真的表示不同动作。 |
| `zh-nominalization` | advisory | 有限动词加双字名词模式；不进行词性分析。 |
| `zh-marketing-adjective` | advisory | 内置空泛修饰语词表；不能证明没有依据，也不能要求删除原文程度或虚构数据。 |
| `zh-passive` | advisory | 正则识别 `被`、`受到`、`遭到` 等被动表达；可能匹配名词或固定搭配。 |
| `zh-barrier-phrase` | advisory | 内置无信息引导语词表；不能判断该表达是否承载语气或衔接功能。 |
| `zh-synonym-rotation` | advisory | 文件内出现词表中的多个中文近义词时提示；不能确认它们描述同一概念、对象或动作。 |

例如 `Start the service. Launch the browser.` 可以触发近义词提示，但两个动作语境不同，不能据此强制改成同一动词。advisory 应结合原文判断，不能通过自动替换直接“修复”。

## 计数与源位置

英文沿用按兼容 Python 的空白分隔非空白片段的词数算法，不作语言学分词：附着标点不会额外拆分，独立标点片段仍计 1。例如 `a;b` 计 1，`a ; b` 计 3；未被识别为 Markdown 结构的独立 `-`、`===` 各计 1。排除代码围栏、缩进代码、inline code、列表标记、ATX 标题开头的 `#` 标记、表格分隔行及水平线或 Setext 分隔行。行内代码视为不计词的独立操作数，防止其两侧单词被正则拼接成新的短语。

中文不按空白分词：每个汉字计 1，连续西文或数字串整体计 1；两个数字之间的半角小数点保留在串内，`3.14`、`v2.1`、`v2.1.3` 各计 1。空白或其他标点断开连续串，`HTTP v2.1`、`API.HTTP` 各计 2；汉字不与相邻西文串合并。标点与空白本身不计，行内代码同样不计数。因此 `words` 和 `per_100_words` 在 `--language zh` 下的单位是「字」，与英文词数不可互换。句长要求的适用范围见[中文规范](chinese-writing-rules.md#计数口径)；检查器不自动判断输入是否为解释性长文。

连续串判定按 Unicode 码点进行：扩展平面的西文字母或数字不拆成两个字符，`𝐀B` 和 `𝟏𝟐` 各计 1；扩展平面的汉字仍逐字计数，`𠀀A` 计 2。半角小数点只连接两侧的 Unicode 十进制数字（`\p{Nd}`），不限 ASCII：`𝟏.𝟐`、`１２.３`、`1.𝟐` 各计 1；字母或其他数字类别不能借点连接，`𝐀.𝐁`、`①.②` 各计 2。
紧随汉字的变体选择符（U+FE00–U+FE0F、U+E0100–U+E01EF）不另计字，也不使汉字与后续西文串合并；例如 `丸\uFE00` 重复 16 次计 16，`丸\uFE00A` 计 2。检查器不核验具体变体序列是否登记；其他组合标记、孤立选择符和西文组合串沿用原有计数行为。源位置仍按原文码点计算，不删除选择符。

输入沿用 Python 兼容行切分：行界为 CRLF（`\r\n`，整体计一个行界）、LF（`\n`）、CR（`\r`）、VT（`\v`）、FF（`\f`）、U+001C 至 U+001E、NEL（U+0085）、LS（U+2028）和 PS（U+2029）。这些字符先切分逻辑行，再进行 Markdown 块识别；连续行界产生空行。

段落内的软换行合并后检查句长，不能通过将一个长句拆成多个逻辑行规避阈值。空行与 Markdown 块边界分隔检查单元；完成上述行切分后，空行只含 ASCII 空格和 Tab，只有其他非行界 Unicode 空白（例如 U+00A0、U+3000、U+001F）的行不会终止段落。列表仍受容器缩进约束：此类空白行没有达到条目内容要求的 ASCII 空格或 Tab 缩进时会退出列表，因为不支持懒惰续行；普通段落及保持所需缩进的列表空白行仍不断段。普通标题正文和表格正文单元格也参与检查。

非行界、非 ASCII 空白的原始行也可以打开语法段落，即使去除兼容空白后的暂时正文为空，后续同容器的 Setext 下划线仍可利用这个打开状态。因此 `U+00A0` 后另起一行的 `===` 计 0，空条目后按内容缩进的 `U+00A0` 和 `===` 也计 0；空条目后直接接缩进的 `===` 则计 1。语法段落打开不等于已存在末条有效内容：纯兼容空白段落在结束时不加入有效内容索引；ASCII 空行和 ASCII 空列表正文本身不打开段落。

行号和列号指向**原始输入**，从 `1` 开始；行号按上述逻辑行界递增，每个行界之后列号重新从 `1` 开始。列号按 Unicode code point 计算，不是 UTF-16 单元数或终端显示宽度。跨行问题定位到该问题在原文中的起始位置。删除或遮蔽 inline code 后不会把其后的报告位置左移。

UTF-8 输入中的 BOM 保留为正文字符并占一列，不自动去除；因此带 BOM 的首行不会自动按列表、标题或围栏识别。英文与中文悬空连词检查统一使用 Python 兼容尾部空白：U+001F 属于空白，U+FEFF（BOM）不属于空白，也不会在尾部自动移除。

## 支持的 Markdown 子集

- 列表标记前允许 `0` 至 `3` 个空格；支持 `-`、`*`、`+`、数字加 `.` 或 `)`；标记后使用 ASCII 空格。条目正文只含 ASCII 空格和 Tab 时视为空条目。普通段落只允许非空条目打断，有序标记的起始编号还须为 `1`；其他序号和空条目仍作为段落正文检查，符合 Setext 下划线的行优先作为标题边界。按标记及间隔宽度识别续行，检查最后一条有效内容是否为悬空连词。续行允许空格与 Tab 混合缩进，Tab 展开到下一个四列制表位；报告列号仍按原始字符计算。
- 围栏使用反引号或波浪号，开启与关闭标记必须各占独立逻辑行，前面仅有空格或 Tab 缩进。关闭围栏必须与开启围栏使用相同字符，且长度至少相同，尾部只允许 ASCII 空格和 Tab；围栏内另一种字符不会结束当前围栏。顶层围栏会结束之前的列表归属，列表内缩进围栏保留该归属；非空行去缩进离开列表时，列表内围栏随容器结束，该行重新参与块识别。
- ATX 标题的开头标记后允许 ASCII 空格或 Tab，也允许没有正文。标题、水平线及 Setext 下划线在顶层最多缩进三列，在列表内相对内容缩进最多三列；列表内的标题正文保留条目归属，参与最后有效内容的悬空连词检查。
- 相对缩进的水平线和 Setext 下划线先于列表标记判定，不因同时匹配列表标记而丢失条目归属。Setext 只作用于当前同一容器的段落，离开旧条目后不会用旧段落吞掉新空条目；普通段落的 Setext 优先级保持不变。表格预读分隔行时排除匹配列表标记的行，避免将新条目吞作表格边界；正常的 `|-|-|`、`-|-` 和带对齐冒号的短分隔行仍按同一容器要求识别。
- 空列表条目保留列表容器，但 ASCII 空格和 Tab 正文不打开段落：其后的缩进代码仍排除，没有前置段落且不构成水平线的 Setext 下划线仍作为正文。空条目的内容缩进固定为标记前缩进加标记长度再加一列，额外行尾空格和 Tab 不增宽容器。非空或非行界 Unicode 空白正文不按空条目处理，继续使用完整标记间隔宽度。
- 既有列表子集不限制有序标记的 ASCII 数字位数，也不限制标记后的 ASCII 空格数量；五个及以上间隔空格后的非空正文仍按列表正文检查，不转换为 CommonMark 的缩进代码。悬空连词在条目首行时定位到列表标记，在续行时定位到末尾连词的原始行列。
- 水平线使用至少三个相同的 `-`、`*` 或 `_`，标记之间及尾部可有 ASCII 空格和 Tab。Setext 下划线使用一个或多个 `=` 或 `-`，尾部可有 ASCII 空格和 Tab，且必须紧随已打开的段落；没有前置段落的独立等号行仍作为正文检查。
- 忽略围栏代码和受支持的缩进代码；普通段落或列表段落未被空行或块边界终止时，深缩进续行仍合并检查。空行后的缩进代码继续忽略；列表内代码需比列表内容至少多缩进四列。
- 非空行去缩进离开列表时，先结束旧列表段落，再按顶层规则重新识别该行；此时达到四列缩进的行可作为顶层缩进代码排除，不会被旧列表段落阻挡。此行为沿用不支持懒惰续行的容器契约，不影响普通段落的深缩进续行或保持列表内容缩进的续行。
- inline code 使用等长反引号串开启和关闭，允许跨行及包含不同长度的反引号串。开启处连续反斜杠按奇偶决定是否转义第一个反引号；代码内部反斜杠不转义闭合标记。代码不参与词语检查，后续报告仍使用原始行列号。
- 常见 pipe 表格在正文块状态下通过表头及紧随的分隔行识别，支持列表内另起行且按内容缩进的表格；表头及分隔行均须留在同一列表容器，分隔行缩进还须小于代码缩进阈值。每个分隔单元格至少含一个短横线，允许两端的对齐冒号；单元格及行两端只去除 ASCII 空格和 Tab，其他 Unicode 空白不能补成合法分隔行。竖线前连续反斜杠为奇数时转义竖线，为偶数时仍分隔单元格或结束外侧边界；行内代码中的竖线不分隔单元格。列数相同的正文行按单元格分别检查，活动表格中的深缩进数据行不当作缩进代码；表格分隔行不参与正文检查。代码块内的表头不影响正文；空行、列表标记、标题、水平线、代码块或列数不符的行结束表格。列表内表格在去缩进离开列表时结束，新表格须重新匹配表头及分隔行。
- 新表头不能采用达到代码缩进阈值的行；活动表格因列数不符而结束后，不会把该深缩进行重新用作新表头。活动表格中列数匹配的深缩进数据行仍按单元格检查。
- 表格单元格均保留在全局检查与计数中，但行内代码遮蔽后仅含兼容空白的单元格不覆盖列表的末条有效内容。只含行内代码操作数的单元格仍是有效内容，防止误将代码之前的连接词报告为悬空。

它不是完整 CommonMark 解析器。引用块内的列表、使用 Tab 分隔标记的列表、懒惰续行和完整嵌套列表语义不在支持范围内。在一行已经识别为列表项后，同一行正文仅按普通文本和 inline code 处理，不再识别任何新的 Markdown 块，例如 ATX 标题（`- # Foo bar`）、水平线（`- ***`）、围栏（`- ```python`）或 pipe 表头（`- | a | b |`）；要使用这些块，应另起逻辑行并按列表内容缩进。整行先被认作水平线的 `- - -` 不进入列表项分支，仍按现有块优先级处理。ATX 标题可选的结尾 `#` 标记不会去除，因此可能计入词数。缩写、小数、复杂嵌套结构等可能影响句子切分或分段，不应将解析结果视为正式语言学分析。

## 检查器不能证明的事项

检查器不比较原文与改写稿，因此不验证事实、条件、数量、否定、要求强度、时间关系或 actor 是否保持。它也不检查所有技能规则，例如名词堆叠、每句一条指令、段落主题及安全条件覆盖范围，更不核验官方批准词典。

结果为零只表示当前启用规则在受支持输入范围内没有发现问题。用户应按技能的保真流程对照原文；合法的保真例外可以保留并在用户要求分析时说明。
