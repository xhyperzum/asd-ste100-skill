# 中文简明技术写作规范

本规范把 [ASD-STE100](https://www.asd-ste100.org/) 的受控语言原理适配到**中文**技术写作，与英文 STE 规则并列，不取代也不改写英文流程。

## 定位与边界

- 本规范是**面向中文的适配规范**，不是官方标准的中文版，也不是对英文规则的逐句翻译。ASD-STE100 只批准英文用词，中文没有对应的官方批准词典；本规范不核验用词是否「批准」。
- 句长上限、计数口径和词表都是**本项目定义的适配值**，与英文的 20/25 词**不是换算关系**，两组数字不能互相替代。
- 适用：工具说明、错误消息、操作步骤、智能体间指令、状态报告等说明性文字。
- 不适用：创意写作、依赖语气的说服性文案。可以分析其中的技术主张，但不能为了简洁改变其程度或意图。
- 改写遵循 [SKILL.md 的保真优先级](../SKILL.md#优先级与保真要求)。中文的 `必须`、`应当`、`可以` 分别对应要求、建议和许可，其保持方式以共享规则为准。
- 原文的数据属性与边界不明时的优先级，统一遵循 [SKILL.md 的输入与执行指令边界](../SKILL.md#输入与执行指令的边界)。中文分支不另行定义这套规则。

## 计数口径

中文不用空格分词，因此检查器的英文词数口径不能直接套用。本规范按以下规则计数：

- **汉字**：每个汉字计 1；紧随汉字的变体选择符用于选择字形，不另计字数。
- **西文与数字**：连续的西文或数字串整体计 1（如 `API`、`v2.1`、`HTTP`）；两个数字之间的半角小数点保留在连续串内（如 `3.14`、`v2.1.3`）。空白或其他标点断开连续串，`HTTP v2.1` 计 2；汉字仍逐字计数，不与相邻西文串合并。
- **标点与空白**：不计。
- **代码**：围栏代码、缩进代码和行内代码不参与检查，也不计入字数。

句长目标：

| 文本类型 | 上限 |
|---|---|
| `instruction`（操作步骤、指令） | 20 字 |
| `description`（说明、错误描述） | 30 字 |

解释性长文不自动对整篇施加句长硬性门禁；其中真正的操作步骤或指令仍适用 `instruction` 上限，用户明确要求每句不超过 30 字时仍按该要求检查。不能仅因文本属于仓库文档而豁免句长要求。

分句以全角句号 `。`、叹号 `！`、问号 `？` 为界，允许句末闭合引号或括号（如 `。”`、`。）`）。分号 `；` 不作为分句边界，而是单独的结构问题。

## 核心结构规则

下表是本规范**中文侧执行规则**的登记表。规则正文以 [SKILL.md 的核心改写规则](../SKILL.md#核心改写规则) 为共享来源，本表只记录中文差异、阈值和检查深度，不重复规则正文。

| 规则 | 执行要求 | 保真例外或边界 | 检查深度 |
|---|---|---|---|
| 句长 | 指令不超过 20 字，说明不超过 30 字；阈值与英文的 20/25 词不是换算关系。 | 同 SKILL.md「句长」的例外。 | 可机械检查 |
| 每句一条指令 | 同 SKILL.md 同名规则；中文的「应当」对应建议。 | 同 SKILL.md 同名规则的边界。 | 部分提示 |
| 分号 | 同 SKILL.md「分号」规则；中文检查器同时识别全角 `；` 与半角 `;`。 | 同 SKILL.md「分号」规则的边界。 | 可机械检查 |
| 列表化 | 同 SKILL.md「段落和列表」规则。 | 同 SKILL.md「段落和列表」规则的边界；中文要求强度词对应关系见定位与边界。 | 部分提示 |
| 段落主题 | 同 SKILL.md「段落和列表」规则；中文检查器按 `。！？` 计数句子。 | 同 SKILL.md「段落和列表」规则的边界；检查器不判断主题是否不同。 | 部分提示 |
| 列表项末尾连接词 | 同 SKILL.md 同名规则；中文检查器提示「和、或、以及、并且、或者、同时」等后缀。 | 后缀匹配无法确定词边界，会误报「总和」「饱和」等词；确认后再处理。 | 部分提示 |
| 完整句子 | 同 SKILL.md 同名规则。 | 同 SKILL.md 同名规则的边界。 | 人工 |
| 安全说明 | 同 SKILL.md 同名规则。 | 同 SKILL.md 同名规则的边界。 | 人工 |
| 术语一致 | 同 SKILL.md 同名规则及其 Strict、STE-flavored 模式要求。 | 同 SKILL.md 同名规则的边界。 | 部分提示 |

## 词汇与句式建议

以下为启发式建议，需结合语境判断，不能自动替换。

| 规则 | 提示内容 | 保真例外或边界 |
|---|---|---|
| 名词化 | 同 SKILL.md「动词与短语动词」规则；中文着重「进行／作出／开展／实施／加以／予以／从事 + 名词」结构。 | 同 SKILL.md「动词与短语动词」规则的边界。 |
| 空泛修饰语 | 同 SKILL.md「程度与修饰语」规则；中文提示词包括「赋能、闭环、抓手、无缝、极致、领先」。 | 同 SKILL.md「程度与修饰语」规则的边界。 |
| 被动表达 | 同 SKILL.md「主动语态」规则；中文检查器提示「被、受到、遭到」等表达。 | 同 SKILL.md「主动语态」规则的例外；正则可能匹配名词或固定搭配。 |
| 无信息引导语 | 同 SKILL.md「程度与修饰语」规则；中文提示词包括「众所周知、不言而喻、值得注意的是」。 | 同 SKILL.md「程度与修饰语」规则的边界。 |

## 与检查器的对应

`scripts/ste-lint.mjs` 的 `--language zh` 实现上表中**可机械检查**的部分：

- 硬性（`advisory-free`，计入退出码）：`zh-semicolon`、`zh-long-sentence`。
- 建议（`advisory`，不影响退出码）：`zh-dangling-conjunction`、`zh-multi-action`、`zh-nominalization`、`zh-marketing-adjective`、`zh-passive`、`zh-barrier-phrase`、`zh-list-required`、`zh-paragraph-topic`、`zh-synonym-rotation`。

```bash
node scripts/ste-lint.mjs --language zh --text-type instruction instructions.md
node scripts/ste-lint.mjs --language zh --text-type description --json description.md
node scripts/ste-lint.mjs --language zh --list-rules
```

完整 CLI、Markdown 子集和搜索边界以[检查器说明](linter.md)为准。

## 检查器不能证明的事项

检查器不比较原文与改写稿，因此不验证事实、条件、数量、否定、要求强度、时间关系或施事者是否保持。它以启发式提示列表化、段落主题和术语一致，但不判断要求是否真的对应不同操作、主题是否真的不同，或术语是否真的同义。它不检查完整句子和安全条件覆盖范围，也不核验用词是否符合任何官方词典。

结果为零只表示当前启用规则在受支持输入范围内没有发现问题。改写后必须按保真流程对照原文；合法的保真例外可以保留，并在用户要求分析时说明。

## 与英文规范的关系

英文文本使用 [SKILL.md](../SKILL.md) 中的规则和英文检查器；中文文本使用本规范。两者共享同一套保真优先级和数据／指令边界，但计数口径、句长上限和词表彼此独立。标准背景和来源见[写作规则背景](writing-rules.md)。
