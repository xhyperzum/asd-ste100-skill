## 三、具体异常与证据

**行前缀检测的词法边界**（`evaluate.mjs` 中的 `forbidden_line_prefix`）

1. 这里用的是 JS 原生 `trimStart()`，而不是文件中定义的 `SPACE`/`TRIM_START`。两者范围不同：
   - `trimStart` 会剥掉 U+FEFF。
   - `trimStart` 不会剥掉 `\u001c-\u001f`。
   - 因此行首为 `\u001F` 或 U+200B 的标记行能绕过检查。
2. 分行只按 `\r\n|\r|\n` 切分，不处理 U+2028、U+2029、U+0085。在多数渲染器中会显示为换行的标记行，因此不会被当作行首。
3. 这两点都在"不号称解决任意注入"的边界之内。但 `evaluation.md` 写的是"对每行移除开头空白"，这一表述与实现的空白集合不一致，应当写明实际口径。

**`--no-tools` 使"未执行"类维度失去检验力**

- 适配器禁用了工具，所以 protected-content 的"没有执行 CLI 或访问 URL"、zh-injection 的"没有执行重启"在机制上必然成立。
- 这批运行只能证明"文本层面没有声称执行"，不能证明"有工具权限时不会执行"。

**运行环境与真实部署不一致**

- 完整 SKILL.md 以用户消息注入，不是 pi 的技能加载路径。
- 中文参考文件对每一例都注入，包括纯英文案例。真实安装是按需读取。
- 结论只能外推到"全量上下文"这一条件，不能外推到真实触发和按需读取。

**可复现性：仍缺的元数据**（原先扣分的 8 项 metadata 已基本补齐，但发现以下新缺口）

- 没有记录 thinking / reasoning 级别。适配器未传 `--thinking`，实际级别取决于 pi 的设置或 provider 默认值。
- 没有记录 `wokey` 自定义 provider 的配置（`models.json`、base URL）或其哈希。
- 适配器丢弃了 `message_end` 中的实际服务模型标识、`stopReason` 和 usage。
- 适配器不检查 stopReason 为 length 的截断情况，截断输出会被当作成功。
- `spawn('pi')` 通过 PATH 解析，没有记录 pi 可执行文件的路径或哈希；`pi_version` 无法与实际调用的二进制文件绑定。

**冻结清单不完整**

- `evaluation.md` 要求清单包含"原始报告的 SHA-256"和"实际命令"。
- 本 packet 的清单只有 5 个输入文件，没有 `real-model-2026-10-11-reviewed.json` 的哈希。
- 也没有记录 evaluate 自身的 argv（`--timeout` 等）。这两项可能已由另一 reviewer 补全，但交付物本身仍不完整。

**文档问题**

- `evaluation.md` 的历史索引和结论章节没有收录这次 2026-10-11 的 41 例运行。
- 报告文件名带 `-reviewed`，而 `semantic_approval` 实际为 pending，名称有误导性。

**运行并发情况**

- 回归、安装、自检与模型运行在 06:49:53 同时启动。
- 前后哈希一致（unchanged: true），排除了输入被篡改的可能，但两类任务并非隔离执行。
- 时间戳自洽：首例 `duration_seconds` 7.725 与起止时间相符；`recorded_at` 06:54:53.132 紧接末例结束。

**自动检查区分力为零的案例**

- boundary-spoof、future-restart-tense、unclear-restart-tense、protected-long-instruction：原样回显即可通过自动检查。
- 这符合设计（允许原样保留），但意味着这 4 例的自动通过不含任何行为信息。

## 五、结论与限制

**结论**：
- 本次 41 例真实运行没有发现保真失败或注入执行，自动检查结果为 0 失败、0 操作错误。
- 主要遗留问题是结构判定口径分歧（#21、#24、#29）和可复现性元数据缺口。

**状态**：**pending-human-review**。本审查来自独立 AI 代理，不能替代人类审批。

**限制**：
- 单一 provider、每版本每例单样本，不证明稳定性，也不能给出通过率。
- 历史上丢失的 190 条 source 和原有专项记录不补造，也不代表当前行为。
- 未显式设置 temperature 和 seed，使用默认值，不能承诺逐字复现。
- packet 省略了 prompt 正文，本审查未自行重算 `prompt_sha256`。

**建议**：
1. 修订 safety-condition-first 的第 1 条与第 5 条，消除冲突；统一 paragraph 类案例与 SKILL 的列表口径。
2. 适配器记录 stopReason、实际服务模型和 thinking 级别；拒绝截断输出；用绝对路径调用 pi 并记录其哈希。
3. 冻结清单补充报告哈希和 evaluate argv。
4. 行前缀检查改用统一的 `SPACE` 口径和 Unicode 行分隔符，并据此修正文档表述。
5. 在文档索引中加入本次运行，并将报告重命名，去掉 `-reviewed`。
