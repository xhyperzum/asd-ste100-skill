## A：空 table cell 不覆盖末条有效内容

修复位置 `scripts/ste-lint.mjs:377`。处理顺序仍是创建 Segment、记录原始位置、遮蔽 inline code、加入全局 `segments`；只有加入 item 的有效检查段时，才排除遮蔽后仅含 Python 兼容空白的单元格。`references/linter.md:108` 准确声明全局段与有效尾项的区别。

最小输入：

```text
- x
  | a | b |
  |-|-|
  | c or | |
```

当前实测词数 5、硬性 `dangling-conjunction` 为 `[4, 7]`、CLI 退出 `1`。全局段顺序仍为 `x`、`a`、`b`、`c or`、空单元格；item 的有效索引为 `[0, 1, 2, 3]`。末个空 cell 不再让 `c or` 的有效尾项失效。

正反核对：

- 空单元格放第一列、最后一列、多列中间，或在尾项之后追加整行全空数据，均保留所有全局 Segment 与列数，只排除 item 有效索引中的空内容。
- 空白使用空串、ASCII 空格、Tab、NBSP、U+3000、U+001F；配合四种列表标记、2/3/5 列、中英文和不同有效内容位置。432 项逐一断言全局段数、有效索引数组、词数、规则等级及原始位置。
- 代码单元格测试普通同长反引号、含异长反引号、代码内 pipe/分号以及代码两侧 Unicode 空白。遮蔽后的 `CODE_OPERAND`（U+FFFC）不是兼容空白，**仍加入有效索引**；代码文本不计词，不触发代码内部的分号。不能用“词数为零”或“代码不参与规则”代替“是否有效内容”的判断。
- BOM 单元格不被当作空白丢弃：英文单独 BOM 计一片段，中文 BOM 不计字，但两者均保留有效索引，且不错误回看之前的连接词。
- 当整个表头和全部数据 cell 都为空时，全局段仍保留；列表首行 `x and` 或 `甲和` 仍是最后有效内容，位置为列表标记 `[1, 1]`。
- 在 `c or` 与空 cell 后追加有效的 `done;` 续行，尾项正确变为 `done;`，悬空连词消解；分号仍按原始位置报告。

非 BMP 和组合字符位置也逐项核验。例如 `😀c or` 位于原例第一数据 cell 时，硬性报告 `[4, 8]`，没有因排除其他空 cell 或遮蔽代码而左移。

## B：同行列表正文不再次识别块

`references/linter.md:110` 明确：已经识别列表标记后，同行的 ATX、HR 或 fence 字样作为普通列表正文，不再次解析成块。使用这些块应另起逻辑行并按内容缩进。此声明不是将此前受支持的另行块删除，也不新增完整 Markdown 语义。

## C：Unicode 空白不断段仍受列表缩进约束

`references/linter.md:89` 现在明确两层条件：非行界 Unicode 空白不结束普通段落；在列表中，仍须达到条目要求的 ASCII 空格/Tab 缩进，否则退出容器。此前已经排除懒惰续行，不能将“不断段”解释为无条件继续 item 归属。

- `- foo\n\u3000\n  bar and`：词数 3，末段 `listId=null`，无列表硬性悬空连词，CLI 退出 `0`。
- `- foo\n  \u3000\n  bar and`：词数仍为 3，末段归属 item 0，硬性报告 `[3, 7]`，CLI 退出 `1`。
- 四种标记 × 中英文 × U+001F/NBSP/U+3000 × 内容宽度减一/相同/加一，72 项均核对末段归属、词数、等级对应规则与原始位置。中文不足缩进时同样退出，但符合缩进时仅报告 advisory，不升级为硬性。
- 三种 Unicode 空白在普通 13+13 词段落中仍保持单段，词数 26、长句 `[1, 1]`；没有通过把所有 Unicode 空白都当 ASCII 空行来达到表面通过。

该声明澄清的是已经存在的容器边界。源码逐字节差异核对和上面的正反探针均确认：B/C 没有实现层的支持范围回退，历史逻辑行集合、BOM 保留、代码排除与非空 gap 契约不变。
